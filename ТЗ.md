# Network Traffic Controller (NTC) — Техническое задание

## 1. Общие сведения

| Параметр | Значение |
| :--- | :--- |
| **Наименование проекта** | Network Traffic Controller (NTC) |
| **Цель** | Десктопное приложение на Python с GUI (PyQt6) для мониторинга сетевой активности приложений, ведения чёрного списка и блокировки сетевого трафика с системой уведомлений |
| **Целевая платформа** | Windows (основная), Linux (дополнительная) |
| **Язык и стек** | Python 3.11+, PyQt6, psutil |
| **Архитектура** | MVC |

> **Важно:** механизмы перехвата и блокировки трафика сильно зависят от ОС. Реализация для Windows и Linux различается и описывается отдельно (см. п. 4.1).

---

## 2. Функциональные требования

### 2.1. Мониторинг сетевого трафика

- **Сбор данных:** отслеживание сетевых соединений в реальном времени и сопоставление с процессами (PID, имя).
- **Метрики:**
  - имя процесса и PID;
  - объём отправленных (`bytes_sent`) и полученных (`bytes_recv`) данных;
  - количество активных соединений;
  - удалённые IP и порты.
- **Обновление:** интервал 1–2 секунды без блокировки интерфейса; скорость рассчитывается по дельте между опросами.

### 2.2. Чёрный список (Blacklist)

- **Управление списком:** добавление, редактирование, удаление записей.
- **Объекты блокировки:**
  - имя процесса / исполняемого файла;
  - IP-адрес (IPv4 / IPv6);
  - домен (опционально, см. ограничения в п. 5).
- **Хранение:** сохранение между сессиями (JSON или SQLite — см. п. 4.1).

### 2.3. Блокировка трафика приложений

- **Механизм:** предотвращение отправки пакетов процессами из чёрного списка.
- **Реализация:**
  - Windows: `pydivert` или `netsh advfirewall`;
  - Linux: `python-iptables` или `subprocess` + `iptables`/`nftables`.
- **Ограничение:** блокировка на уровне соединений, **а не** убийство процесса.

### 2.4. Уведомления

- **Триггер:** попытка соединения приложения из чёрного списка.
- **Содержание:** имя приложения, целевой IP/порт, время попытки.
- **Тип:** toast-уведомления PyQt или системные уведомления ОС.
- **Настройка:** возможность отключения для конкретных приложений или глобально.

## 3. Требования к интерфейсу (PyQt6)

### 3.1. Главное окно

- **Таблица мониторинга:** `QTableView` с моделью данных (реализация MVC).
- **Панель управления:** кнопки «Обновить», «Очистить», «Настройки».
- **Статусная строка:** общий объём трафика и статус блокировки.

### 3.2. Диалог управления чёрным списком

- Список текущих правил.
- Форма добавления правила (процесс / IP / домен).
- Кнопки «Добавить», «Удалить», «Применить».

### 3.3. Система уведомлений

- Кастомные всплывающие окна PyQt6 (`rbpop`, `pyqt-toast-notification`) или `QSystemTrayIcon`.
- Уведомление поверх других окон, **без кражи фокуса**.

### 3.4. Цели по UI (обязательные к реализации)

В рамках проекта должны быть продемонстрированы:

1. **Диалоговые окна** — модальные и немодальные (`QDialog`, `QMessageBox`, `QInputDialog`, кастомные формы).
2. **Виджеты** — стандартные и кастомные (`QTableView`, `QLineEdit`, `QComboBox`, `QPushButton`, `QLabel`, `QProgressBar`, собственные виджеты).
3. **Работа с несколькими окнами** — главное окно, диалог чёрного списка, окно настроек, окно уведомлений; корректное управление жизненным циклом окон.
4. **База(-ы) данных** — хранение чёрного списка, истории инцидентов и настроек (SQLite предпочтительно; JSON — как минимум для настроек).
5. **Работа с холстом** — графическое представление данных: график скорости трафика (`QGraphicsView` / `QChart` / кастомная отрисовка через `paintEvent`).
6. **Создание исполняемых файлов** — сборка для Windows (`.exe` через PyInstaller) и Linux (бинарник / AppImage).

## 4. Технические требования и архитектура

### 4.1. Стек технологий

| Компонент | Технологии |
| :--- | :--- |
| **Язык / GUI** | Python 3.11+, PyQt6 |
| **Мониторинг** | `psutil` |
| **Блокировка (Windows)** | `pydivert` / `netsh advfirewall` |
| **Блокировка (Linux)** | `python-iptables` / `subprocess` + `iptables` |
| **Уведомления** | `rbpop` / `pyqt-toast-notification` / `QSystemTrayIcon` |
| **Хранение данных** | SQLite (основное), JSON (настройки) |
| **Сборка** | PyInstaller (Windows `.exe`), PyInstaller / AppImage (Linux) |

### 4.2. Архитектура MVC

- **Model** — данные и бизнес-логика: мониторинг (`psutil`), чёрный список, расчёт дельт, доступ к БД.
- **View** — PyQt6-виджеты и окна, не содержат бизнес-логики.
- **Controller** — связывает Model и View, обрабатывает сигналы, управляет потоками.

### 4.3. Архитектура потоков

- **UI-поток:** главное окно и обработка событий.
- **Поток мониторинга:** `QThread` с интервалом 1–2 с, передача данных через сигналы PyQt.
- **Поток блокировки/перехвата:** `pydivert` в отдельном потоке, сигнал на уведомление.

### 4.4. Алгоритм работы

1. **Старт:** загрузка чёрного списка, инициализация мониторинга.
2. **Цикл мониторинга:** получение соединений (`psutil.net_connections()`), сопоставление с процессами, расчёт дельты I/O, проверка по чёрному списку.
3. **Блокировка:** применение правила в файрволе или отбрасывание пакета.
4. **Уведомление:** сигнал в UI для показа всплывающего окна.
5. **Логирование** инцидента в файл и в БД.

### 4.5. Обработка ошибок

- **Отсутствие прав администратора:** предупреждение и режим «только мониторинг».
- **Завершившиеся процессы между опросами:** игнорировать с записью в debug-лог.

## 5. Ограничения и риски

- **Права доступа:** администратор на Windows (WinDivert), `CAP_NET_ADMIN` на Linux.
- **Производительность:** интервал опроса не менее 1 с, кэширование статических данных.
- **Обход блокировки:** процессы с RAW-сокетами могут остаться незамеченными.
- **Блокировка по домену:** требует перехвата DNS или анализа SNI; в первой версии — только IP и процессы.
- **Объём кода:** не менее **500 строк** (не включая код интерфейса).

## 6. Этапы разработки

1. Прототип мониторинга через `psutil`.
2. GUI-каркас PyQt6 с таблицей (MVC).
3. Чёрный список: CRUD + сохранение в БД.
4. Блокировка через `pydivert` / файрвол.
5. Уведомления.
6. Холст: график трафика.
7. Сборка исполняемых файлов (Windows / Linux).
8. Тестирование и отладка.

---

## 7. Критерии приёмки

- Приложение запускается и отображает список активных сетевых приложений.
- Добавление в чёрный список приводит к уведомлению при попытке отправки данных.
- Трафик заблокированного приложения фактически не проходит.
- Интерфейс остаётся отзывчивым во время мониторинга.
- Реализованы и продемонстрированы: диалоговые окна, кастомные виджеты, многоконный интерфейс, БД (SQLite/JSON), холст с графиком трафика.
- Проект собирается в исполняемый файл для Windows и Linux.
- Объём кода (без UI) — не менее 500 строк.
- Архитектура соответствует MVC.
